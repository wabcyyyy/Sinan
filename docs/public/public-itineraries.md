# 公开行程库与复制微调

行程库入口是 `/itineraries`，首页与主导航均可进入。访客可查看路线，登录后复制到“我的行程”，再使用原有对话编辑与确认流程。已有 `/s/{token}` 分享页也支持复制。

首页保留原有“热门城市”和“灵感起点”两排。灵感区沿用四张卡片的封面、标题、主题与横向滚动样式，点击直接查看完整行程，不再预填开场语句；不额外新增“行程分享”一排。探索页的同名四张卡片也直达完整路线，其余尚未扩充的灵感继续支持需求预填。

## 首批内容

内置杭州、成都、北京三条两日规划，以及由原灵感卡片扩充的大理 4 天、首尔 3 天、厦门 3 天、大阪 4 天规划，包含实际地点、逐日建议时段、转场留白和核实提醒。它们标为“司南编辑规划”，不是实地游记、模型运行记录或已预订产品；不编造实时价格、坐标与酒店。用餐仅推荐片区，由用户自行选择。

唯一内容源是 `travel-agent-python/app/services/curated_itineraries.json`。后端直接读取，静态展示通过现有 `scripts/export_contracts.py` 导出到前端生成文件。内置内容使用负数编号，数据库公开内容使用正数编号；无需向用户业务库插入种子行程。

## 用户操作

1. 在行程库按城市或关键词找路线，打开逐日详情；官方信息入口用于出发前核实。
2. 点击“复制到我的行程”。未登录时先登录，再返回原路线；登录后再次点击确认复制。
3. 复制不调用模型、不产生 AI 费用。副本归当前用户，日期和预算留空，不继承作者的会话、账目、分享权限或预订。后续 AI 编辑沿用正常额度和确认机制。
4. 作者在自己的行程详情打开“预览并发布”，检查公开投影后点击“确认公开发布”。只有路线完整的已完成行程可发布。
5. 发布的是快照。之后私人行程的修改不会自动公开，重新预览并更新后才替换公开版本；也可随时下架。下架后不能继续浏览或新建副本，已经复制的个人行程保留。

公开范围包括标题、人数、路线点位、时段、封面和费用档位。精确金额、私人日期、备注、聊天和账目不公开。标题、点位或照片本身可能含隐私，发布前仍需由作者检查。

## 配置与边界

`TEMPLATE_COMMUNITY_ENABLED=true` 是新安装的默认值；旧 `.env` 不会自动重写。若已有数据库 addon 开关，数据库值优先；管理员可在既有 `PUT /api/admin/addons/template_community` 中设置 `{"enabled": true}`。私有部署可关闭该开关。

仅行程库明确的 GET 路径允许匿名，继续保留路由鉴权依赖及按 IP 限流。发布、下架和复制须登录；所有者校验继续在服务层执行。列表最多展示最近 60 份用户公开规划，再附内置参考路线。

Vercel 静态展示也能浏览以上七条参考路线、复制到当前标签页，并体验“把第二天安排松一点”的固定脚本编辑。它不访问业务 API、不会向公开库发布，刷新保留本标签页副本，重置体验后清除。真实用户内容与 AI 微调须连接完整后端。

## 验证入口

后端 `tests/test_template.py` 覆盖匿名只读、所有者发布、源数据隔离、分享撤销、独立副本及部分交付不可发布；前端 `publicItineraries.test.ts` 覆盖浏览、登录返回、单次复制和明确发布，`demo/transport.test.ts` 覆盖静态副本与编辑隔离。日常按根目录 `verify.ps1` 运行相关检查。
